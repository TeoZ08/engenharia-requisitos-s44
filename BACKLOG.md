# Backlog — Grupo S44

Este documento resume as histórias de usuário registradas como GitHub Issues para o Trabalho Prático de Engenharia de Requisitos.

## Técnica de priorização

Foi utilizada **MoSCoW**:
- **Must**: essencial para o fluxo principal ou para a segurança/autonomia do atendimento;
- **Should**: importante para qualidade, governança ou evolução do produto, mas não bloqueia o fluxo básico;
- **Could**: desejável, porém pode ser simplificado ou adiado no primeiro experimento.

## Escopo do MVP

O MVP considera inicialmente as histórias **S44-US01 a S44-US05**, cobrindo:
1. registro da solicitação;
2. classificação e resposta automática elegível;
3. solicitação de atendimento humano;
4. continuidade do atendimento com contexto;
5. registro do desfecho.

As histórias S44-US06, S44-US07 e S44-US08 permanecem fora do MVP inicial e apoiam governança, administração e evolução posterior.

## Convenção de status

No GitHub, cada história permanece como **Issue aberta** enquanto estiver em `A Fazer`. O fechamento da Issue deverá ocorrer somente quando os critérios de aceitação correspondentes forem considerados atendidos pelo grupo.
